# Модуль поиска повторяющейся потребности

Небольшой учебный модуль на Go, который ищет похожие закупки в синтетических данных. Совпадения предназначены для ручной проверки и сами по себе не доказывают нарушение. В репозитории нет закрытых данных AdalQarau и сторонних зависимостей.

## Репозиторий и воспроизводимость

[Репозиторий adalqarau-assignment-3](https://github.com/RomanVassilchenko/adalqarau-assignment-3). [CI workflow](https://github.com/RomanVassilchenko/adalqarau-assignment-3/blob/main/.github/workflows/ci.yml) выполняет те же проверки, что и [release workflow](https://github.com/RomanVassilchenko/adalqarau-assignment-3/blob/main/.github/workflows/release.yml). Эта работа подготовлена для версии `v0.2.0`. После публикации тег позволит получить точный исходный код этой версии:

```sh
git clone --branch v0.2.0 --depth 1 https://github.com/RomanVassilchenko/adalqarau-assignment-3.git
cd adalqarau-assignment-3
./check.sh
```

Workflows используют Ubuntu 24.04 и Go 1.26.7. Эта версия указана в официальных [метаданных загрузок Go](https://go.dev/dl/?mode=json&include=all). Для локального запуска установите Go 1.26.7 и выполните:

```sh
go version  # go version go1.26.7 ...
./check.sh
go run ./cmd/screen -input testdata/contracts.csv -output /tmp/repeated.csv -window-days 30
```

Скрипт `check.sh` проверяет форматирование, `go vet`, тесты и сборку, затем запускает CLI-проверки результата, повторяемости, неверного ввода и защиты от совпадения входного и выходного файлов. Release workflow собирает исполняемые файлы для Linux, macOS и Windows, архитектур amd64 и arm64, и публикует файл контрольных сумм `SHA256SUMS`.

## Входные данные и правило

CSV должен содержать ровно семь полей в указанном порядке:

```text
contract_id,customer_bin,contract_date,item_name,unit,quantity_units,amount_kzt
```

Идентификатор договора, BIN заказчика, предмет и единица измерения должны быть непустыми после удаления внешних пробелов. Идентификаторы договоров должны быть уникальными. BIN рассматривается как непустой ключ: модуль не проверяет его соответствие юридическому формату. Дата задается как `YYYY-MM-DD`; количество и сумма — неотрицательные десятичные целые числа в диапазоне `int64`. Идентификатор сохраняется с учетом регистра после удаления внешних пробелов. Предмет и единица переводятся в нижний регистр и очищаются от внешних пробелов; BIN очищается от пробелов и сравнивается с учетом регистра. Пустой CSV отклоняется, CSV только с заголовком допустим.

Модуль сравнивает все пары договоров (`O(n²)`). Пара подходит, если BIN, нормализованные предмет и единица, количество и сумма совпадают, а разница календарных дат не превышает включительное значение `window-days`. Более ранняя дата становится базовой; при одинаковых датах базовым считается договор, который раньше встретился во входном CSV. Пары выводятся в порядке обхода строк входного файла. Все договоры хранятся в памяти; поиск и выдача результатов требуют `O(n + m)` памяти, где `m` — число совпавших пар. В библиотеке отрицательное окно возвращает пустой результат, а CLI отклоняет его.

Выходные поля: `base_contract_id,repeated_contract_id,customer_bin,days_between,rule_version`; версия правила — `repeated-need-v2`. Для `testdata/contracts.csv` и окна 30 дней результат имеет вид:

```csv
base_contract_id,repeated_contract_id,customer_bin,days_between,rule_version
A,B,111,30,repeated-need-v2
B,D,111,2,repeated-need-v2
```

CLI принимает флаги `-input <file>`, `-output <file>` и `-window-days <days>` (по умолчанию 30). Входной и выходной аргументы не могут указывать на один файл. При успешном запуске код завершения равен 0, при ошибке аргументов или флагов — 2, при ошибке чтения файла или CSV — 1. CSV полностью проверяется до открытия выходного файла. При успешном запуске существующий выходной файл перезаписывается.

## Структура и технологии

`screen.go` отвечает за чтение и проверку CSV, нормализацию и поиск пар. `cmd/screen` — оболочка командной строки. `screen_test.go` проверяет ошибки CSV, несовпадения ключей, границы дат, порядок и полный диапазон дат. Синтетический пример находится в `testdata/contracts.csv`.

В стандартной библиотеке Go уже есть средства для CSV, флагов, дат и целых чисел, поэтому сторонние пакеты не нужны. Go объединяет код и тесты в одном небольшом модуле и позволяет собирать автономные исполняемые файлы. Такой пакетный алгоритм можно короче написать на Python, но стандартная сборка Go, встроенные тесты и переносимые бинарные файлы упрощают CI и выпуск артефактов.
